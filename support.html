What is going wrong?

Start with the issue you can see. Connecting BOS, setting it up in an app and fixing the app itself are different jobs.

1

I can’t connect

Ask your coding AI to check whether Cloud BOS is available and signed in. Request the connection result without changing anything.

2

BOS isn’t responding in my project

Ask whether BOS is set up for this exact app and whether that setup still matches the saved files. Review a current repair plan before approving any changes.

3

My app has a problem

Check whether the app opens and whether an ordinary task, such as saving, still works. Describe the failure separately from any BOS connection issue. BOS helps during development and must not become an application runtime dependency.

Prepare a short support summary

Copy this request into your coding chat, then review the answer before sharing it:

Check Cloud BOS for this exact project without changing anything. Tell me whether the connection works, whether BOS setup is active and verified in this app, and what remains incomplete. If a check fails, report the observed error separately from any suspected cause. Prepare a short support summary with my coding tool, plugin version if visible, safe status codes and a support reference if available. Exclude tokens, passwords, source code, raw logs, full prompts and personal or customer information.

The summary should include:

  • environment: Codex, Claude Code or Base44;
  • installed Cloud BOS plugin version, when visible;
  • what went wrong: connection, app setup, feature access, billing or an unavailable service;
  • the connection and app-setup status, including exact status codes if your coding AI can safely provide them;
  • a support reference, if one was created; exclude private project contents.

Never send

  • passwords, API keys, access tokens or private keys;
  • private source code or full prompts;
  • raw logs, database exports or screenshots with private data;
  • customer, student, employee or tenant records;
  • private BOS instructions, internal development files or full project memory.

If Cloud BOS is unavailable

Your app should keep working when Cloud BOS is unavailable. Pause changes that depend on BOS checks, keep the last checked project state and record the connection problem. Keep sign-in protections in place and never paste an access token into your code.

Disconnecting BOS and removing its setup from an app are separate actions. Review any removal plan first; it must preserve your app, its data and normal operation.

Contact and escalation

For technical help or beta access questions, use the contact supplied with your private-beta invitation. Include the reviewed summary above. There is no public support form yet. For policy, privacy or billing questions, use the email contact listed on the policy pages.

If a password or token may have been exposed, someone can see another customer’s information, or changes are damaging data, stop using the affected BOS connection and mark your report urgent.
