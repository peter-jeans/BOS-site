Set up BOS in Base44

For the Base44 AI app builder. The connection is account-wide; add the skill separately to each workspace where you want it.

You need a Base44 Builder plan or higher, room for another MCP connection and room for a skill in the selected workspace. Confirm the app belongs to that workspace before setup.

Get access and connect Cloud BOS

Open the BOS Client Portal to get help onboarding your app and obtain the approved Cloud BOS connection URL. The portal address opens the onboarding app; use the separate MCP connection URL supplied with your access in Base44.

In Base44, open your profile menu and choose Settings → MCP connections → Add custom MCP.

Approve and check setup for your app

Do this separately for each app or repository, after connecting your development tool. Cloud BOS prepares a plan first; you decide whether to apply it.

Once setup is approved, you should not need to remember a rebind command. Each new or resumed session checks your connection, the exact project and its saved working records before continuing.

What does a complete connection check restore?

The check confirms current access, verifies the installed project setup and reloads the accepted plan, active intention and available project records. Being signed in alone does not prove that all of this is ready.

A rebind preserves the existing project and connection. It reports missing files, changed records or unresolved memory clearly; it does not invent decisions or silently accept changes. Connection checks run before questions about missing product requirements.

The customer plugin restores its approved public project records. The original private owner connection, called privatecloudBOS or foundercloudBOS, uses its existing private project framework. Installing the customer plugin does not switch a private project to that route.

One-time host trust, sign-in and approval of the initial project setup still apply. If automatic checks are unavailable, the host must report that gap. This preview is not evidence that every host has passed live verification.

Use Cloud BOS to discover this exact app or repository with bos_project_discover, read any existing specification and ask only for missing decisions. Explicitly ask me to accept the displayed baseline before preparing its current setup plan with bos_project_governance_plan. Show the exact proposed files, permissions and rollback or removal boundary, together with the current plan hash. Stop for my approval before writing anything. If governance is already active, verify it and report any drift instead of reinstalling.
  1. Check the exact app or repository, intended work and proposed changes. Approve only the current plan and its plan hash. New durable proposals have no response deadline. BOS refreshes execution checks when you return; review again only if the action or relevant conditions change. Legacy timestamped proposals keep their original terms.
  2. Let your coding tool apply the approved plan and reopen the exact files it changed. For the Base44 customer route, stay in your app. When BOS reaches the AI Controls step, review the exact instructions it supplies, then open Models → AI Controls → Custom Instructions. Paste the approved text, save, reload and reopen. Setup stays incomplete until an independent read-only check verifies the exact saved text. A “saved” message alone is not verification. Codex or Claude Code can still perform a separately labelled external setup; that does not count as the Base44-only customer test.
  3. Have Cloud BOS activate and verify the installed result. A governed project must report project_governance_state: GOVERNED_ACTIVE and project_binding_verified: true. A successful connection alone is insufficient.

On later sessions, ask to use Cloud BOS and check the current project before work. If sign-in, binding or verification fails, resolve that status before relying on governed changes.

Disconnecting or removing governance

Disabling a connection or plugin stops that tool from using Cloud BOS. Removing a project's governance is a separate, reviewed operation: request a removal plan for that exact project, approve its scope and verify the result. Application source, data and runtime behavior must be preserved.
