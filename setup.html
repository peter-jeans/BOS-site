What does a complete connection check restore?

The check confirms current access, verifies the installed project setup and reloads the accepted plan, active intention and available project records. Being signed in alone does not prove that all of this is ready.

A rebind preserves the existing project and connection. It reports missing files, changed records or unresolved memory clearly; it does not invent decisions or silently accept changes. Connection checks run before questions about missing product requirements.

The customer plugin restores its approved public project records. The original private owner connection, called privatecloudBOS or foundercloudBOS, uses its existing private project framework. Installing the customer plugin does not switch a private project to that route.

One-time host trust, sign-in and approval of the initial project setup still apply. If automatic checks are unavailable, the host must report that gap. This preview is not evidence that every host has passed live verification.

  3. Have Cloud BOS activate and verify the installed result. A governed project must report project_governance_state: GOVERNED_ACTIVE and project_binding_verified: true. A successful connection alone is insufficient.

On later sessions, ask to use Cloud BOS and check the current project before work. If sign-in, binding or verification fails, resolve that status before relying on governed changes.

Disconnecting or removing governance

Disabling a connection or plugin stops that tool from using Cloud BOS. Removing a project's governance is a separate, reviewed operation: request a removal plan for that exact project, approve its scope and verify the result. Application source, data and runtime behavior must be preserved.
